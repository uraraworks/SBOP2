# 押せる物（ボール・岩・箱）の作り直し計画書

> 作成日: 2026-09-13
> 対象: マップ上の Push=1 NPC（ボール・岩・箱）の押し処理全般。

---

## 1. 背景

- マップ1のボール（`sys_char` CharID 989「ボール」、MoveType=1(STAND), Push=1, Block=0）が、押すと3〜4パーツ分ワープする／プレイヤーが素通りする不具合を本番で確認した（2026-09-13）。
- 原因は複数の変更が重なったもの:
  - 2026-06-16 の d595fcf: 押し1回で即16px Move し、歩数を積んで移動ステートにする方式に変更。
  - 4fd38d8: 押し相手検出を自キャラ現在位置〜前方の掃引矩形にし、同一座標スキップを撤去。
  - ピクセル移動化により、プレイヤーが1px進むごとに `REQ_PUSH` を送るようになった。
- この結果、サーバーは要求が届く限り歩き続け、`MOVE_STOP` で32px超の差が出るとスナップされてワープに見える。ボールは Block=0 でプレイヤーを止めないため素通りも起きる。`m_dwMoveWaitOnce` は速度計算に効いていない。
- 元仕様（2008年 a7b959e〜）: 押し1回で16px前へ。前が塞がると `Move(bTurn=TRUE)` で逆向きに16px（逆向きはマップ判定のみで他キャラを見ない）→プレイヤーと入れ替わる。これは押せる物すべてに共通の処理だった。

---

## 2. 決定済みの仕様（ユーザー合意 2026-09-13）

1. 押せる物（Push=1 の NPC）はボール・岩・箱で共通処理とする。CHARMOVETYPE_BALL(2) は「動いている間だけアニメが変わる」ことと「壁での入れ替わり」だけが違い。
2. 押せる物はプレイヤーにとって固い（重なれない）。当たって押すと、行き先が空いていればプレイヤーと一緒に歩く速さで1pxずつ連続して進む。塞がっていればプレイヤーも止まる。離すと止まる。敵・他の押せる物も障害物になる。
3. 押す向きは押している人のキャラの向き（上下左右4方向）。斜め移動中でもキャラの向きで押す。
4. 位置の決定はサーバーが行う。押している本人は送信元セッションで決める（改造クライアント対策）。サーバーは以下を確認して空いている所まで進める（途中まで受理）:
   - 速度（経過時間 × `GetCharMovePixelsPerSec` × 1.1 + 8px）
   - 本人座標の妥当性
   - 接触（すき間4px以下）
   - 行き先を1pxずつ（マップと本人以外の全キャラ）
5. 押し合い: サーバーに届いた順に処理する。反対側のプレイヤーは障害物になるので、押せる物がプレイヤーと重なったり置き去りになったりしない。
6. 表示: 押している本人の画面では押せる物を先に動かし（予測）、ずれたときだけ補正する。見ている側は押せる物もプレイヤー(PC)と同じ Dead Reckoning(DR) で先読みする（ウェイポイント補間だと100〜200ms遅れ、DRで先読みされる押している人がボールにめり込んで見えるため）。受信のたびに確定座標へ `SetPos` してから `StartPredictedMove` する（表示位置から先読みし直すだけだと32px未満の遅れが溜まり、押している人に追い抜かれた。PCの位置同期と同じ手順）。停止通知で DR を止め、確実に STAND にする（`CInfoCharCli::ForceStopMoveState`。`ChgMoveState` は移動中の立ち系をキューに積むだけで、押せる物はキューを処理しないため）。押している本人の画面は予測のまま。予測終了から1000ms以内に届く自分の押し更新は DR せず直接合わせる（行き過ぎて戻るのを防ぐ）。
7. 入れ替わり（BALL のみ。岩・箱は壁の前で止まり、押している人も止まる）:
   - **条件**: ボールの1px先が障害物で塞がっていて、本人が接したまま同じ向きへさらに進もうとしている。
   - **開始**: クライアントは入れ替わりを始める直前に、ボールの今の座標を通常の PUSH で1回送る（壁までの最後の数pxが送信の間引きで未送信だと、サーバーのボールが壁の手前に残って開始できないため）。サーバーは開始位置 P0 を要求から逆算する: k＝ボール目標が B0 から -d へ下がった量、P0＝申告の本人座標から d へ k 戻した位置。接触判定は P0 の本人矩形と B0 のボール矩形で行う。
   - **動き**: 本人が向き d に s px 進むと、ボールは逆向き -d に s px 押し出される（プレイヤーの横をすり抜けて後ろへ移っていく）。その間、本人とボールの d 方向の当たり判定はしない。本人が止まればボールも止まる。当たり矩形は端を含むので幅は right-left+1（横32/縦16px）。
   - **完了**: 本人の d 軸の移動量が幅以上になったら完了。ボールの下げ量は min(移動量, 幅) で打ち切り、横方向は B0 のまま。最後の位置を SWAP・離した印で送る。
   - **一時停止**: キーを離しても入れ替わり状態は保ち、同じ向きへ再び動けば続きから。サーバーは専有者の要求が2000ms途絶えたら打ち切り、クライアントは1800msで先に手放す。
   - **後ろが塞がっている場合**: 開始前にボールの逆向きの経路（本人の幅ぶん）を1pxずつ確認し、空いていなければ入れ替わらず本人も止まる。途中で他のプレイヤーが割り込んだら二人とも止まる。
   - **サーバー検証**: 開始時の本人位置 P0・ボール位置 B0・向き d を記録し、ボールの目標が B0−(P−P0) の d 軸成分と一致し横方向は不変、合計移動量が本人の幅以下、経路が空いていることを確認する（壁の無い場所での入れ替わりやワープを改造クライアントで作れないようにする）。入れ替わり中のボールは開始した本人が専有し、他の人の押しは終わるまで却下する。
   - **途中で本人が向きを変えた場合**: サーバーがボールを新しい向きへ本人の2倍速で自走させ、専有者の矩形を四方に24px広げた範囲から出たら止める（サーバーが知る本人位置は通信の遅れで10〜20px後ろにあり、重なりが解けた瞬間で止めると本人がすぐ重なって押せなくなるため。ユーザー確認で24pxに決定）。塞がれたら、そこで止める。押している本人の画面では、自走中は推測航法を使わず、届いた座標へ直接合わせる（行き過ぎて本人の方へ戻るのを防ぐ）。DB 配置の NPC は `m_pLibInfoCharSvr` が NULL なので、自走開始時に `SetLibInfoChar` する。
   - **押せる物の停止時**: CHAR_STATE の STAND で古い確定位置へ戻さない（ワープの原因だった）。
8. マップ1のボール（CharID 989）は、新処理を本番に入れた後に管理画面で MoveType=2(BALL) に変更する（データ作業は別対応）。

## 3. 通信の案

- `CPacketCHAR_REQ_PUSH` を作り替える（旧クライアント互換は不要。ブラウザ版とサーバーは同時デプロイのため）: 押せる物ID、向き(0-3)、種別(PUSH/SWAP)、押せる物の目標座標、本人の座標、クライアント時刻を含める。100ms毎・向き変更時・離したときに送る。
- `CHAR_RES_PUSH` を新設（押せる物ID・確定座標・受理/却下）。却下時の補正送信は1秒1回までとする。
- 周囲への配信は既存 `ProcChgPos`（MOVE_START / 100ms毎の DIR_CHANGE / STOP）を使う。押せる物は `GetInterpolatedNPCPos` を通さず `m_nMapX/Y` を直接送る。押せる物は `ProcChgPos` の100ms間引きをしない（`m_bChgPos` は押し受理時にしか立たないため頻度は押し要求以下。間引くと更新が捨てられ間隔がばらつく）。
- `CPacketCHAR_REQ_PUSH` に `m_bRelease` を追加。キーを全部離した最終送信と、接触を失った瞬間の送信で TRUE。サーバーは受理/却下の後に、本人が押していた移動中の押せる物なら即 STAND（MOVE_STOP を早め、見る側の行き過ぎ→戻りを防ぐ）。150ms タイムアウト停止は欠落時の保険として残す。
- 管理画面で NPC の座標を変えたときは、旧位置の周囲に DELETE、新位置の周囲に RES_CHARINFO を送って画面に反映する（従来は値の書き換えだけで画面が変わらなかった）。押し状態も解除する。

---

## 4. クライアントの案

- 押せる物用の当たり判定関数を新設する（1px先で判定、`m_bPush` なら Block=0 でも固い、既に重なっていれば対象外＝脱出可）。`GetFrontCharIDPush` の掃引矩形は廃止してこれに置き換える。`GetCollisionRectOnce` は `GetDrawDirection` 依存なので向きは引数で渡す。
- 予測時、サーバー位置との差が24px以内なら補正しない。却下時は確定座標へ100msかけて寄せる。
- アニメ: BALL は MOVE に切り替わった時だけコマを戻す（見る側は毎パケット MOVE を受けるため毎回戻すと転がらない）。STAND 型の押せる物（岩・箱）は MOVE 中も立ちモーション（`GetMotionInfo`）。

---

## 5. 削除・置換する旧処理

- サーバーの歩数方式（`m_nPushCount`/`m_nMoveCount` での押し）と `TimerProcMOVE` の押し用停止判定。
- `REQ_PUSH` の BALL 例外（`m_bPush` 不要の分岐）。
- 押しの `Move(bTurn)` 経路。
- Common の掃引矩形。
- クライアントの `m_dwMoveWaitOnce` 設定と `OnXChar` の BALL 分岐（Xキーで2歩押し）。

いずれも該当箇所のファイル・行番号は目安として書く。実装時に確認すること。

## 7. 未決事項・リスク

- 当たり幅が異なる押せる物が出た場合の入れ替わり終了条件（今の押せる物は全て32×16）。
- サーバーの1px判定とクライアント判定のずれによる引き戻し、予測の24px許容でずれが見えにくいこと、本人座標の許容を広げすぎると遠隔押しになること。
- ボールの抜けていく先（本人の背中側）が塞がっている場合・途中でそこへ割り込まれた場合は、サーバーのテストとクライアントの1pxごとの確認で守っているが、実機では未確認。

## 進捗（2026-09-15）

S1〜S3 完了。ローカル実機で確認済み: 4方向・斜めの押し（押す向きはキャラの向き）、離すと止まる、すり抜けない、壁・敵の前で止まる、止まって押し直してもワープしない、ページ再読込＋再ログイン後も押せる、サーバー停止＋DB でサーバー上の位置が画面と一致。

実機確認で直したこと（要点のみ）:
- サーバーの押し判定がDB配置NPCの `m_pInfoMap`(NULL) を使っていた→マップIDから引く
- 接触判定を「目標位置」で±4px、直角方向も±4px
- 経過時間の上限300ms・再読込（5秒以上の時刻逆行）で基準取り直し・ログイン時リセット
- 要求距離0は動かさず受理
- クライアントは却下で即確定座標へ、押せる物はウェイポイントキューに乗せず最新座標へ、接触を失った瞬間に即送信
- `CTextOutput::Write` が255バイト超の行を黙って捨てていたのを修正

診断ログの切り替え: サーバー `PUSH_DEBUG_LOG`（`MainFrameRecvProcCHAR.cpp` と `InfoCharSvr.cpp`）、クライアント `PUSH_CLIENT_DEBUG_LOG`（SboCli の `MainFrameRecvProcCHAR.cpp`・`StateProcMAP.cpp`・`InfoCharCli.cpp`）。どちらも通常0。入れ替わりの判定（SWAP開始判定 lat/k/w/ct/cs/rt 等）とクライアントの SEND/RES/RECV/JUMP/DR を出せる。ブラウザのコンソールで `[PushDbg]` を検索できる。
