# イラスト調グラフィック移行 計画書

最終更新日: 2026-10-22

## 目的

ドット絵の描き足しが大変なので、Codex(GPT Image)で生成できるイラスト調（高解像度ドット絵風）に移行し、効率と今風の見た目を両立する。

## 試作で確認できたこと

2026-10-21〜22 に試作。素材は `tmp/illust_trial/`（コミット対象外）。

- 参考画像を Codex に渡して `codex exec` で生成。タイル・キャラ(4方向×歩き4コマ)・置き物で画風がそろう。キャラは16コマとも顔・服・頭身が一致した
- 地面タイル（草・石畳・土・砂・木の床・洞窟床）は継ぎ目ほぼなし。水面は横に継ぎ目、壁は「上端」と「本体」を分けないと縁が繰り返す。境界は3x3オートタイル（草地の中の石畳/石畳の上の草地）で生成可能
- タイルだけだとツクール風に平たく見える。雰囲気の大半は「升目からはみ出す大物の一枚絵（噴水・木・街灯・建物入口）＋影＋光」が作る
- 影は絵に描かせず、輪郭を右下へ倒してプログラム生成すると光源がそろう。木は木漏れ日のまだら影が効く
- 色: 生成物は黄・オレンジ寄り（Lab b* 平均 32 vs 参考 18.5）。Lab の平均/標準偏差合わせ（Reinhard法）で参考の落ち着いたベージュに寄る。残差は色ではなく大きな影のメリハリと影の青み
- 生成は1枚あたり数分〜15分程度かかることがある

## 現状の描画の前提（調査結果）

- 素材は16px単位。内部で2倍（32px タイル）にして 480x480 の m_pDibBack（余白32px付き）に描き、ブラウザで CSS `--game-scale` によりさらに2倍。元絵1ドット=画面4x4px
- 拡大率を1か所で変える仕組みはない。拡大先サイズ（MgrDraw.cpp のパーツ16→32 BltStretchNearest、オブジェクト、アイテム、キャラ cx×2）と位置計算（LayerMap.cpp の `32 + x*32` 系、GetDrawMovePos/GetDrawMapPos/GetDrawPos、アイテム・管理者デバッグは個別計算）の2系統に散らばる
- RGBA 読み込みは MgrGrpData.cpp の Read() にあるが、Blt 系は画素アルファを使わない（カラーキー一致＋全体 byLevel のみ）
- マップオブジェクトは m_sizeGrp マス分のパーツID格子（16px片を2倍）、前後関係は行単位（オブジェクト→キャラ→重ねパーツ、m_nHideY で補正）。保存は sys_map_object / sys_map_object_anime / sys_map_objectdata、管理画面は webroot/js/views/map-object-place.js
- キャラは 16px 1枚絵キャラと 2x2 合成キャラ（32pxセルを2倍＝2x2マス）。メインは 2x2 合成キャラ
- UI は各ウィンドウの m_pDib から m_pDibBack へ +32 で Blt。ブラウザでは文字を canvas キューで JS 描画。DOM オーバーレイは C++ 報告座標 -32px 補正

## 設計方針

大前提: サーバー/ゲーム座標（32px単位）は変えず、クライアントの描画だけ2倍。

| 項目 | 方針 |
| --- | --- |
| 画面 | ワールドを 960x960 バッファに描き、CSS 拡大をやめ等倍表示 |
| UI | 当面 480 のまま別バッファに描き最後に2倍で重ねる（ドット絵UIのまま。イラスト化は後日） |
| 座標 | ゲーム座標→描画座標の変換を1か所に集約 |
| 旧素材 | 拡大を2倍→4倍にするだけで表示。新旧混在で段階的に差し替える（移行期間の混在は許容済み） |
| 新素材 | RGBA PNG＋画素アルファ合成。GrpLayout に「イラスト版タイル(64px)」「イラスト版キャラ(128pxセル, 4方向×4コマ)」カテゴリを追加 |
| オブジェクト | マップオブジェクトに一枚絵モード（画像名＋足元基準）。当たり判定・m_nHideY・配置・管理画面は既存を流用 |
| 仕上げ | 影の自動生成（まだら・青み）と色合わせ LUT を既存ライティングの段に追加 |

## S1 確認結果

- Windows（2026-10-22）: 見た目は元版と同等。描画は最大11〜20ms
- Mac・Chrome（2026-10-25）:
  - 通常マップ（βマップ）: canvas 960x960、歩き回って描画 最大9ms
  - 夜マップ（βマップの Level を一時的に50にして確認）: 減光は正常。ライティング約10ms込みで描画 最大19ms。半解像度化は今のところ不要
  - スマホ表示（375x812）: canvas が幅375に収まり、横スクロールなし。仮想パッドとミニログも崩れなし
- 未確認: キャラ光源・マップ配置ライトの光の位置（光源を持つキャラ・マップで見ていない）

## S2 実装メモ

- マップパーツに `m_wGrpIDIllust`（DB列 `sys_map_parts.GrpIDIllust`、API `grpIdIllust`、0=なし・1始まり）。シート `SboGrpData/res/illust/tile_NN.png`（1024x1024 RGBA、64pxセル16x16、セル=(id-1)%256）
- ワールド描画（960）だけイラスト版を使い、下地の上に画素アルファで重ねてから pile を重ねる。等倍・管理画面系は従来の16px
- 管理画面のマップパーツ編集に番号入力とプレビュー。画像アップロードは illustTile カテゴリだけ RGBA 必須
- tile_01.png は試作 `tmp/illust_trial/tiles_raw.png`（256px×16種）を64pxに縮小して並べたもの（セル1草A/2草B/3石畳A/4石畳B/5土/6水/7花壇/8石垣上面/9壁/10木床/11砂/12洞窟/13〜16境界・石段）

## S4 実装メモ

- マップオブジェクトに `m_strIllustFile` / `m_nIllustOffX` / `m_nIllustOffY`（DB列 IllustFile/IllustOffX/IllustOffY、API illustFile/illustOffX/illustOffY）。画像は `SboGrpData/res/illust/object/<名前>.png` と影 `<名前>_shadow.png`（同じキャンバスサイズ）。`obj/` は .gitignore に当たるので `object/`
- 基準: 一枚絵の下端中央を格子の下端中央（m_ptPos は格子の左下マス）に合わせ、補正を足す。前後関係は既存の行ループ（m_nHideY=0 なら最下行で並ぶ）
- 影は地面と重ねパーツの直後、オブジェクト・キャラより前にまとめて描く
- 素材変換: `python3 tools/illust/make_obj.py tmp/illust_trial SboGrpData/res/illust/object`（マゼンタ抜き・縮小・影生成。出力の offY を位置補正Yに入れる）。横に広い物はずらし影、細い物は右下へ倒した影
- 既存のタイルで組んだ噴水などを置き換えるときは、そのパーツのイラスト版タイル番号を石畳にして下地だけ残し（当たり判定は既存パーツのまま）、重ねパーツは `ILLUSTTILE_HIDE`(0xFFFF) で960描画から消す。「重なる」系ビットも外す
- 始まりの町（ローカルDBのみ）: 噴水(45,32) 5x8、街灯8本 1x3、縦ベンチ2 1x4、横ベンチ(46,33) 3x1

## リスク・注意

- 描画ピクセル4倍（ライティング用バッファも）。S1で実測、重ければライティングを半解像度で計算
- 個別計算の位置（アイテム・管理者デバッグ）の取りこぼし
- 管理画面のマップエディタも 16/32px 前提のため、イラスト素材プレビュー対応が後で必要
- 管理画面の画像アップロードはパレットPNG限定の検証がある（d8ae349）。イラスト系カテゴリは RGBA を許可する必要
- Web版は LoadLocalTitleAssets と Load() の二重ローダー。新素材は両方に足す
